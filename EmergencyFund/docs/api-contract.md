# Контракт API «Подушка безопасности»: вклады и цель

Версия 1. Аутентификации пока нет (будет добавлена позже, тогда появится код 401).

## Общие правила

- Базовый адрес: `/api`.
- Формат тела запроса и ответа: JSON, `Content-Type: application/json`.
- Имена полей в JSON — camelCase.
- Даты — строки в формате `YYYY-MM-DD`, например `"2026-11-03"`.
- Перечисления — строки, например `"deposit"`.
- Деньги и ставки — числа. На сервере тип `decimal`.
- Неизвестные поля в теле запроса — ошибка 400.

## Формат ошибок

Все ошибки возвращаются в формате ProblemDetails (RFC 9457), `Content-Type: application/problem+json`. В каждом ответе есть `traceId` — по нему ошибку можно найти в логах сервера.

**400 — ошибка в данных запроса** (валидация или бизнес-правило). Поле `errors`: имя поля → список сообщений. Ключи — имена полей в C#, с большой буквы (`Sum`, `Name`), а не имена из JSON. Ошибка, не относящаяся к конкретному полю, приходит под ключом `""`.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "Sum": ["Сумму можно менять только у накопительного счёта"]
  },
  "traceId": "00-e2ab94a7b6e9468c97b669798f923418-e555fafb6b602c8f-00"
}
```

**404 — ресурс не найден.** Тело — ProblemDetails без `errors`.

**500 — ошибка сервера.** Только общий заголовок и `traceId`: текст исключения и трасса клиенту не передаются, они записываются в лог.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.6.1",
  "title": "Внутренняя ошибка сервера",
  "status": 500,
  "traceId": "00-5c701b6b153544ffbd011f605797cd26-637a8b8d8e21750f-00"
}
```

## Эндпоинты

| Метод | Адрес | Что делает | Успех | Ошибки |
|---|---|---|---|---|
| GET | `/api/deposits` | Список вкладов, упорядоченный по `startDate`, при равенстве — по `id` | 200, массив (пустой список — `[]`) | — |
| GET | `/api/deposits/{id}` | Один вклад | 200, вклад | 400 (id не Guid), 404 |
| POST | `/api/deposits` | Создать вклад | 201, вклад, заголовок `Location` с полным адресом вклада | 400 |
| PATCH | `/api/deposits/{id}` | Изменить вклад | 200, обновлённый вклад | 400, 404 |
| DELETE | `/api/deposits/{id}` | Удалить вклад | 204 без тела | 400 (id не Guid), 404 |

## Модель вклада

| Поле | Тип в JSON | Тип в C# | Кто задаёт | Описание |
|---|---|---|---|---|
| `id` | string | `Guid` | сервер | Идентификатор вклада |
| `name` | string | `string` | клиент | Название для пользователя |
| `type` | string | `DepositType` | клиент | Тип: вклад или накопительный счёт |
| `sum` | number | `decimal` | клиент | Сумма в рублях |
| `interestRate` | number | `decimal` | клиент | Годовая ставка **в процентах**: `15` означает 15 % |
| `startDate` | string | `DateOnly` | клиент | Дата открытия |
| `term` | number \| null | `int?` | клиент | Срок в месяцах; `null` у накопительного счёта |
| `capitalization` | string | `Capitalization` | клиент | Капитализация процентов и её период |
| `endDate` | string \| null | `DateOnly?` | сервер | Дата окончания; `null` у накопительного счёта |
| `estimatedSum` | number \| null | `decimal?` | сервер | Оценка суммы в конце срока; `null` у накопительного счёта |

## Перечисления

`type`:

- `deposit` — вклад со сроком, досрочное снятие с потерей процентов;
- `savingsAccount` — накопительный счёт, снятие в любое время, без срока.

`capitalization`:

- `none` — без капитализации (проценты не прибавляются к сумме);
- `daily` — ежедневно;
- `weekly` — еженедельно;
- `monthly` — ежемесячно.

## Правила валидации (ответ 400)

| Поле | Правило |
|---|---|
| `name` | обязательно, от 1 до 50 символов, не из одних пробелов |
| `type` | обязательно, одно из значений перечисления |
| `sum` | больше 0 |
| `interestRate` | больше 0 и не больше 100 |
| `startDate` | обязательна, не позже текущей даты (местная дата сервера) |
| `term` | для `deposit` обязателен и больше 0; для `savingsAccount` должен быть `null` |
| `capitalization` | обязательно, одно из значений перечисления |

## Вычисляемые поля

- `endDate` = `startDate` + `term` месяцев. У накопительного счёта — `null`.
- `estimatedSum` — оценка суммы в конце срока с учётом капитализации, округлённая до копеек (округление половины — от нуля, `MidpointRounding.AwayFromZero`). У накопительного счёта — `null`.
- Расчёт упрощённый: банк считает проценты по фактическому числу дней, поэтому реальная сумма может немного отличаться.

## PATCH: что можно изменить

Тело запроса содержит только изменяемые поля. Поля, которых нет в теле, не меняются. Пустое тело `{}` — ошибка 400 (ключ `""`).

| Поле | Можно менять |
|---|---|
| `name` | для любого типа |
| `sum` | только для `savingsAccount`; для `deposit` — ответ 400 с ошибкой под ключом `Sum` |

Правила для переданных полей: `name` — от 1 до 50 символов, не из одних пробелов; `sum` — больше 0.

После изменения сервер пересчитывает вычисляемые поля и возвращает вклад целиком.

## Примеры

### Создание вклада

Запрос:

```http
POST /api/deposits
Content-Type: application/json

{
  "name": "Вклад на год",
  "type": "deposit",
  "sum": 150000,
  "interestRate": 15,
  "startDate": "2026-11-03",
  "term": 12,
  "capitalization": "monthly"
}
```

Ответ:

```http
HTTP/1.1 201 Created
Location: https://localhost:7096/api/deposits/3f2b8c1e-7a4d-4e9b-9c2f-1d5e6a7b8c90
Content-Type: application/json

{
  "id": "3f2b8c1e-7a4d-4e9b-9c2f-1d5e6a7b8c90",
  "name": "Вклад на год",
  "type": "deposit",
  "sum": 150000,
  "interestRate": 15,
  "startDate": "2026-11-03",
  "term": 12,
  "capitalization": "monthly",
  "endDate": "2027-11-03",
  "estimatedSum": 174113.18
}
```

POST /api/deposits

  "sum": 300000,

  "startDate": "2026-10-01",

### Изменение суммы накопительного счёта

Запрос:

```http
PATCH /api/deposits/8a1c2d3e-4f5a-4b6c-8d7e-9f0a1b2c3d4e
Content-Type: application/json

{
  "sum": 350000
}
```

Ответ: `200 OK` и вклад целиком с новой суммой.

## Принятые решения

- **PATCH, а не PUT.** Меняются только название и сумма накопительного счёта, остальные поля после создания не меняются.
- **Отдельные типы запросов** (`CreateDepositRequest`, `UpdateDepositRequest`). В них нет полей, которые задаёт сервер (`id`, `endDate`, `estimatedSum`), поэтому клиент не может их подменить (защита от overposting).
- **PATCH возвращает 200 с телом.** После изменения суммы сервер пересчитывает вычисляемые поля, и клиенту не нужен отдельный GET.
- **Пустой список — 200 и `[]`, а не 404.** Ресурс «список вкладов» существует, просто в нём нет элементов.
- **`decimal` для денег и ставки.** Десятичное хранение без ошибок двоичного округления.
- **`DateOnly` для дат.** Время и часовой пояс для вклада не нужны.
- **Перечисления строками.** Читаемо и не ломается при изменении порядка значений в `enum`.
- **Ставка в процентах.** Пользователь вводит ставку так, как её пишет банк; перевод в долю делает сервер.
- **Ошибки бизнес-правил — доменное исключение.** Сервис бросает `BusinessRuleException` с полем и текстом, глобальный обработчик превращает его в 400 того же формата, что и ошибки валидации. Выбрано ради простоты; цена — по сигнатуре метода сервиса не видно, что он может отказать.
- **Порядковый номер вклада не хранится.** Это вопрос отображения, его считает фронтенд.
- **Капитализация одним полем.** Вместо пары «есть ли капитализация» + «период» — одно перечисление со значением `none`. Противоречивые комбинации невозможно записать, отдельные правила валидации не нужны.
- **Даты передаются в ISO, показываются как ДД.ММ.ГГГГ.** API передаёт `YYYY-MM-DD`: однозначно, сортируется как строка, стандарт для JSON. Формат отображения — забота фронтенда.

# Цель подушки

Цель у пользователя одна, поэтому у ресурса нет id: один адрес `/api/goal`. Пользователь задаёт расходы в месяц и на сколько месяцев нужен запас. Всё остальное сервер вычисляет при каждом запросе, потому что «накоплено» меняется вместе с вкладами.

## Эндпоинты

| Метод | Адрес | Что делает | Успех | Ошибки |
|---|---|---|---|---|
| GET | `/api/goal` | Цель с вычисленным прогрессом | 200, цель | 404 — цель ещё не задана |
| PUT | `/api/goal` | Задать цель: создать, если её нет, или заменить целиком | 200, цель | 400 |
| DELETE | `/api/goal` | Удалить цель | 204 без тела | 404 — цели нет |

## Запрос PUT

Все поля обязательны: PUT заменяет цель целиком.

| Поле | Тип в JSON | Тип в C# | Описание |
|---|---|---|---|
| `monthlyExpenses` | number | `decimal` | Расходы в месяц, рубли |
| `months` | number | `int` | На сколько месяцев расходов нужен запас |
| `monthlySavings` | number | `decimal` | Сколько пользователь откладывает в месяц, рубли |

## Правила валидации (ответ 400)

| Поле | Правило |
|---|---|
| `monthlyExpenses` | обязательно, больше 0 |
| `months` | обязательно, целое, больше 0 |
| `monthlySavings` | обязательно, не меньше 0 |

## Ответ

| Поле | Тип в JSON | Тип в C# | Как получается |
|---|---|---|---|
| `monthlyExpenses` | number | `decimal` | из запроса |
| `months` | number | `int` | из запроса |
| `monthlySavings` | number | `decimal` | из запроса |
| `targetAmount` | number | `decimal` | `monthlyExpenses × months` |
| `currentAmount` | number | `decimal` | сумма `sum` всех вкладов и счетов |
| `progressPercent` | number | `decimal` | `currentAmount / targetAmount × 100`, два знака, `AwayFromZero`; может быть больше 100 |
| `remainingAmount` | number | `decimal` | `max(0, targetAmount − currentAmount)` |
| `monthsToGoal` | number \| null | `int?` | `remainingAmount / monthlySavings`, округление вверх; `0`, если цель достигнута; `null`, если цель не достигнута, а `monthlySavings = 0` |

## Пример

Вклады на 200 000 ₽ в сумме.

Запрос:

```http
PUT /api/goal
Content-Type: application/json

{
  "monthlyExpenses": 50000,
  "months": 6,
  "monthlySavings": 15000
}
```

Ответ:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "monthlyExpenses": 50000,
  "months": 6,
  "monthlySavings": 15000,
  "targetAmount": 300000,
  "currentAmount": 200000,
  "progressPercent": 66.67,
  "remainingAmount": 100000,
  "monthsToGoal": 7
}
```

`monthsToGoal`: 100 000 / 15 000 = 6,67, округление вверх даёт 7.

Цель не задана:

```http
GET /api/goal

HTTP/1.1 404 Not Found
Content-Type: application/problem+json

{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
  "title": "Not Found",
  "status": 404
}
```

## Принятые решения

- **Одна цель, без id.** Сейчас нужна только подушка. Цели на отпуск, дом и т. п. потребуют связи вкладов с целями — это расширение на неделю 4.
- **Только PUT, без POST.** У ресурса один адрес и нет id, который нужно было бы присвоить. PUT кладёт по адресу полное состояние цели и идемпотентен: повторный запрос с тем же телом даёт тот же результат. Код 200 и при создании, и при замене.
- **404, когда цели нет.** Фронтенд по одному коду понимает, что нужно предложить задать цель, а поля ответа никогда не бывают `null` из-за отсутствия цели.
- **Хранятся только исходные данные.** Цель, накопленная сумма, прогресс, остаток и срок вычисляются при каждом запросе. Один источник правды: добавил вклад — прогресс изменился сам.
- **Накоплено считается по `sum`, а не по `estimatedSum`.** Подушка — это деньги, доступные сейчас.
- **Остаток не бывает отрицательным.** При перевыполнении цели остаток 0, а процент показывает, насколько цель перевыполнена.
- **Срок округляется вверх.** Неполный месяц — это всё равно ещё один месяц откладывания.
- **Без поля `name`.** Цель всегда одна и та же (YAGNI).
